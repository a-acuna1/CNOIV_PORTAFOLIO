> ACTIVIDAD 07: FILE PATH TRAVERSAL, SIMPLE CASE
  • Nivel: Apprentice
  • Tipo de Explotación: File Path Traversal
  • Objetivo: Explorar la vulnerabilidad de File Path Traversal a través del método de petición "GET" del protocolo HTTP, con el fin de poder leer el archivo /etc/passwd.

1. MARCO TEÓRICO Y FUNDAMENTACIÓN TÉCNICA
  • Concepto: De acuerdo con OWASP, un ataque de Path Traversal (también conocido como Directory Traversal) tiene como objetivo acceder a archivos y directorios que están almacenados fuera de la carpeta raíz web. Al manipular las variables que hacen referencia a los archivos usando secuencias de "punto-punto-barra" (../) o rutas absolutas, permite a un atacante acceder a archivos y directorios arbitrarios en el sistema de archivos, incluyendo código fuente de la aplicación, configuraciones y archivos críticos del sistema.
  • Impacto en la Tríada CIA: Esta vulnerabilidad compromete de manera directa la Confidencialidad de la información, ya que expone datos sensibles del sistema operativo.
  • Perspectiva OWASP: Clasificada dentro de la categoría de Broken Access Control (Control de Acceso Roto), ocurre cuando la aplicación utiliza la entrada del usuario para construir una ruta de archivo sin validar o sanear adecuadamente dicha entrada, permitiendo escapar de la estructura de directorios autorizada.
2. PROCEDIMIENTO Y EVIDENCIAS

Se ingresó a la tienda virtual del laboratorio, en la cual podemos ver que carga varias imágenes de productos.

Durante la fase de reconocimiento pasivo en Burp Suite, se identificó un patrón de diseño inseguro en las peticiones GET hacia el endpoint /image. La aplicación emplea el parámetro filename para la carga dinámica de recursos. Al no existir una abstracción, este parámetro se convierte en un vector ideal para inyectar secuencias de salto de directorio. Para un análisis más profundo usamos la función Proxy de Burp Suite.

Haciendo un análisis rápido podemos ver que el método GET directamente llama a las imágenes, así que intentaremos atacar a través de ellas. Para esto, enviamos la petición al "Repeater" y preparamos el payload eliminando el nombre de la imagen y colocando la ruta del archivo que deseamos ver: ../../../etc/passwd.

Damos clic en "Send" y podemos observar que tuvimos éxito y tenemos acceso al archivo passwd.

3. EXPLICACIÓN DEL PAYLOAD

El parámetro filename indica al servidor qué archivo leer del disco duro. En sistemas operativos basados en Linux, la secuencia ../ instruye al sistema a retroceder un nivel en la jerarquía de directorios.

Al colocar ../../../ forzamos a la aplicación a salir del directorio web asignado y ascender niveles hasta llegar al directorio raíz del sistema /. A partir de aquí, la ruta /etc/passwd le indica que debe entrar a ese directorio y mostrar lo que se encuentre ahí, que en este caso es la lista de usuarios del sistema.

4. MITIGACIÓN RECOMENDADA
  • Evitar entradas directas: Lo más efectivo es evitar, lo más que se pueda, pasar la entrada directa al sistema de archivos. En su lugar, se podrían usar identificadores en una base de datos para localizar un archivo.
  • Validación estricta: Si es estrictamente necesario que el usuario coloque alguna entrada para nombrar algún archivo, se debe implementar una validación robusta (ej. que contenga solamente caracteres alfanuméricos). Así se rechazan en automático instrucciones de escape como ../ o bytes nulos %00.
  • Rutas Absolutas y Canonicalización: Tras recibir la entrada, la aplicación debe anexarla al directorio base estricto y utilizar funciones de canonicalización provistas por el lenguaje de programación (ej. realpath() o os.path.abspath()). Finalmente, el sistema debe verificar de forma rigurosa que la ruta absoluta resultante comience exactamente con el directorio base autorizado antes de proceder con la lectura del archivo.
